PROJECT 02 · DATA ANALYTICS & MACHINE LEARNING

User Journey & Drop-off Analysis

Analysed approximately 20,000 user interactions for a U.S. property & casualty insurance carrier to understand drop-off across the application journey. Used Random Forest to examine behavioural patterns and developed a web prototype incorporating improvements suggested by the analysis.

01 · THE PROBLEM

Understanding where users drop off

Where in the application journey were users most likely to leave — and what could the application team learn from it?

The project focused on understanding user navigation across an insurance application, from the beginning of a journey through completion, error or drop-off.

Historical interaction data was analysed to identify where users were leaving the journey and to examine behavioural patterns associated with those drop-offs.

The objective was not simply to predict an outcome. The analysis was intended to help application owners identify parts of the user experience that warranted closer investigation and potential improvement.

02 · DATA & ANALYSIS

Working with real user journey data

Approximately 20,000 recorded interactions provided the basis for analysing navigation behaviour.

Activity across the webpage was available for analysis, providing visibility into how users moved through the application and where their journeys ended.

The interaction data was prepared and normalised before analysis. The focus was on making the navigation data suitable for behavioural analysis rather than creating an extensive engineered feature set.

Looking at the journey rather than only the final outcome made it possible to examine where drop-off was occurring within the application experience.

03 · MACHINE LEARNING

Using Random Forest to examine drop-off patterns

Machine learning was used as an analytical tool within the broader user journey study.

A Random Forest model was used to examine patterns in the historical interaction data associated with user drop-off. The available data was divided into training and testing datasets using a 60:40 split.

Model performance was evaluated on the held-out test data, with ROC analysis used to assess how effectively the model distinguished between different journey outcomes.

The model was not developed as a production prediction service. Its role was to support the analysis and provide another way of understanding patterns within user behaviour.

04 · FROM ANALYSIS TO PROTOTYPE

Turning findings into application changes

The work went beyond identifying drop-off patterns to exploring how the application experience could be improved.

Findings from the user journey analysis highlighted areas where changes to the application experience could be considered.

Based on the analysis, I developed a web prototype that incorporated suggested changes to the user journey. This provided a tangible way to explore how the findings could translate into changes within the application.

The prototype complemented the analytical report by giving application owners both the underlying analysis and an example of how potential improvements could be reflected in the user experience.

05 · OUTCOME

Supporting application improvement with data

The final output combined analytical findings with a practical demonstration of potential improvements.

The analysis and findings were consolidated into a report for the application owners, providing a data-driven view of user drop-off across the application journey.

Together with the web prototype, the work gave the application team a basis for considering further enhancements to the user experience.

The project connected data analysis, machine learning and application development around a practical product problem: understanding where users were leaving and using that insight to explore how the experience could be improved.
