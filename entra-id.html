01 · ENGINEERING CHALLENGE

Modernizing authentication across 70+ production applications

The challenge was not simply to replace one identity provider with another. More than 70 production applications had to move from SiteMinder to Microsoft Entra ID without disrupting access to business-critical systems.

The application portfolio consisted of .NET and .NET Core applications with existing authentication dependencies. Moving to Entra therefore required application-side engineering alongside identity-platform configuration, while allowing the migration to progress incrementally across the portfolio.

A three-person core team drove the modernization. At this scale, repeating the same authentication engineering independently for every application would have made the migration significantly more difficult, creating the need for a reusable migration approach.

02 · AUTHENTICATION ENGINEERING

Standardizing the recurring application changes required for Entra

Migrating more than 70 applications meant that many of the same authentication changes would otherwise have to be implemented repeatedly. A reusable middleware-based approach was developed to standardize those recurring integration changes and make individual application migrations easier to execute.

The reusable approach handled common parts of the Entra integration, including initiating the authentication redirect, processing the returned authentication response, extracting user information and maintaining the authenticated context required by the application.

This repeatability was an engineering enabler for the migration: individual applications could adopt the common authentication approach while application-specific behaviour could still be handled where necessary.

03 · IDENTITY PLATFORM CONFIGURATION

Configuring identity, provisioning and application credentials

Alongside the application changes, the migration required Microsoft Entra ID configuration for application identities, authentication and centralized access management. The applications themselves were hosted on AWS, so sensitive client secrets used by the integrations were kept outside application source code using AWS Secrets Manager — with identity managed in Microsoft Entra ID and application infrastructure remaining on AWS.

04 · PRODUCTION MIGRATION

Moving applications incrementally from SiteMinder to Entra

Authentication is a critical application dependency. The portfolio was therefore migrated application by application rather than through a single large-scale cutover.

For each application, the existing authentication flow and dependencies were first understood. The reusable integration approach could then be applied, the required Entra configuration completed, authentication scenarios tested, and the application validated before production cutover.

05 · ENGINEERING RESULT

A scalable approach to migrating 70+ applications

With more than 70 applications to migrate, implementing recurring authentication changes independently for every application would have increased both engineering effort and migration complexity. Reusing the common integration approach made the migration more repeatable while still allowing individual applications to be handled according to their own dependencies.

Scale 70+ applications Enterprise applications transitioned from SiteMinder authentication to Microsoft Entra ID.
Engineering Approach Reusable migration pattern Common authentication changes could be reused during migration rather than engineered independently for every application.
