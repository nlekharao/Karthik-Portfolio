01 · ENGINEERING CHALLENGE

Modernizing authentication across 70+ production applications

The challenge was not simply to replace one identity provider with another. More than 70 production applications had to move from SiteMinder to Microsoft Entra ID without disrupting access to business-critical systems.

The application portfolio consisted of .NET and .NET Core applications with existing authentication dependencies. Moving to Entra therefore required application-side engineering alongside identity-platform configuration, while allowing the migration to progress incrementally across the portfolio.

A three-person core team drove the modernization, making a reusable integration approach important to delivering the migration at this scale.

02 · AUTHENTICATION ARCHITECTURE & MIDDLEWARE

Engineering a reusable authentication layer

Instead of implementing the complete Entra authentication flow independently within every application, reusable middleware was developed to provide a common authentication layer across the .NET and .NET Core application portfolio.

The middleware participated in the application's request pipeline. When authentication was required, it initiated the redirect to Microsoft Entra ID. After successful authentication, Entra redirected the user back to the application with the returned token.

The middleware processed the authentication response, extracted the required user information and persisted the returned Entra token in a cookie so the authenticated context could be maintained within the application.

When the token expired, the user was routed through the Entra authentication flow again rather than the middleware implementing a separate token-refresh mechanism.

03 · IDENTITY PLATFORM CONFIGURATION

Configuring identity, provisioning and application credentials

The application authentication flow was backed by Microsoft Entra ID configuration for application identities and centralized access management. Sensitive client secrets required by the integrations were kept outside application code using AWS Secrets Manager.

04 · PRODUCTION MIGRATION STRATEGY

Moving applications incrementally from SiteMinder to Entra

Authentication is a critical application dependency. The migration was therefore handled application by application rather than as a single portfolio-wide cutover.

For each application, the existing authentication flow and dependencies were first understood. The Entra configuration and application integration were then prepared, authentication scenarios tested, and the application validated before production cutover.

05 · ENGINEERING RESULT

From application-by-application authentication to a repeatable integration model

The engineering result was more than the replacement of SiteMinder with Microsoft Entra ID. The migration established a reusable application-side authentication pattern that could be applied across the .NET portfolio while still allowing application-specific handling where required.
